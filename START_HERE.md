# Що робиш ти (Дмитро) — три команди, далі команда працює сама

## 1. Розпакувати і створити репозиторій

```bash
tar -xzf kse-attendance-agent.tar.gz
cd kse-attendance-agent

# один раз: GitHub CLI + jq
brew install gh jq          # macOS
# winget install GitHub.cli jq.jq        # Windows
gh auth login
gh auth refresh -s project  # щоб скрипт міг створити дошку проєкту

COLLABORATORS="логін1 логін2" bash scripts/bootstrap_github.sh
```

Скрипт створить репозиторій `dvasylchuk/kse-attendance-agent`, запушить код,
запросить двох колег, створить 9 міток, 4 мілстоуни, 26 issues із залежностями,
дошку проєкту, увімкне захист `main` і auto-merge.

## 2. Роздати треки

Кинь колегам одне повідомлення:

> Репо: https://github.com/dvasylchuk/kse-attendance-agent
> Прочитай `docs/02-git-workflow.md` і `CLAUDE.md`.
> Твій трек: **A** (`mcp_servers/`) / **B** (`agent/`) / **C** (`docs/`).
> Беремо тікети командою `bash scripts/next_ticket.sh track:A-server`,
> клеймимо коментарем `/take`, робимо PR із `Closes #N`.
> У `main` напряму не пушимо. Рев'ю робить будь-хто з нас двох, не я.

## 3. Далі твоя участь — майже нульова

Що відбувається без тебе:

| Подія | Хто робить |
|---|---|
| людина пише `/take` в issue | бот призначає її, ставить `status:in-progress` |
| відкрито PR | CI ганяє `ruff`, `pytest`, перевірку MCP-сервера і скан на секрети |
| PR апрувнув будь-хто з команди | auto-merge мерджить сам, гілка видаляється |
| issue закрилась | бот знімає `status:blocked` із залежних тікетів і пише в них коментар |
| той коментар | сигнал наступному розробнику (або його Claude Code), що можна починати |

Тобі лишається раз на день глянути:

```bash
gh issue list --state open --label status:ready     # що застоялося
gh pr list --state open                             # що чекає рев'ю
```

І один раз — тікети `D1`–`D4` перед захистом, бо захищаєшся ти сам і маєш
вміти пояснити кожен файл.

## Якщо колеги теж працюють через Claude Code

Кожен запускає свою сесію в клоні репозиторію. `CLAUDE.md` у корені — це
протокол: агент читає, який тікет вільний, клеймить його, робить гілку,
пише код за специфікацією з докстрінга відповідного файлу, ганяє тести,
відкриває PR. Три сесії не конфліктують, бо треки не перетинаються по
каталогах, а синхронізація йде через issues, не через чат.
